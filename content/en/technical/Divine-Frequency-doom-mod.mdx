<Section icon={Wrench} title="How to Identify a Genuine Mod Claim">

A legitimate mod listing should explain what it changes, which game build it supports, and how it interacts with the original installation. Vague claims such as “new Doom weapons,” “full conversion,” or “classic FPS mode” are not enough to establish compatibility.

Use the following comparison before opening a file or changing the game directory.

| Claim type | What it may mean | Evidence required |
|---|---|---|
| Doom-inspired content | A fan project borrowing retro shooter ideas | Screenshots, creator identity, target game clearly named |
| Doom engine mod | A project built for a Doom-compatible source port | Engine or source-port requirements, launcher instructions |
| Divine Frequency add-on | A modification made specifically for this game | Supported game version and installation directory |
| Total conversion | A major project replacing assets or gameplay | Detailed dependencies, backup instructions, version history |
| Gameplay preset | Configuration changes rather than a full mod | List of edited settings and a reversible installation method |

If an official or clearly documented Divine Frequency modification becomes available, use a controlled installation process. Early Access games can change file structures, progression logic, and save behavior between updates, so separating experiments from normal play is especially important.

<Steps>
  <Step num="1" title="Confirm the target game and version">
    Open the official Steam listing and check that the file specifically targets Divine Frequency rather than a standalone Doom source-port project. Compare the mod’s supported version with the build installed on your PC.
  </Step>
  <Step num="2" title="Read the full documentation">
    Review the creator’s installation notes, dependencies, known issues, removal instructions, and update history. Do not rely on a short description, a filename, or a screenshot as proof of compatibility.
  </Step>
  <Step num="3" title="Back up saves and configuration files">
    Copy your saves and important configuration data to a separate folder before testing anything. Label the backup with the date and game version so you can identify the correct restore point later.
  </Step>
  <Step num="4" title="Test outside your main playthrough">
    Use a separate profile or a temporary test save. Start with a short session in an early area and check loading, combat, objectives, menus, and progression before continuing.
  </Step>
  <Step num="5" title="Remove the modification if behavior changes">
    If the game crashes, loses progression, displays missing assets, or behaves differently from the documentation, remove the files and restore the clean installation before testing again.
  </Step>
</Steps>
